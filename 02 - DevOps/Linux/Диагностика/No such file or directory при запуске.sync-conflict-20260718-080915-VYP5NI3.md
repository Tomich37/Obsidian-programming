# No such file or directory при запуске

[[00 Диагностика Linux]]

Если исполняемый файл существует, `No such file or directory` часто относится не к нему, а к необходимому интерпретатору или динамическому загрузчику.

Типовые причины:
- в shebang указан отсутствующий путь, например `#!/bin/bash`;
- Windows-окончания строк превращают путь в `/bin/bash\r`;
- отсутствует ELF loader или библиотека;
- бинарник собран для другой архитектуры;
- битая символическая ссылка.

```bash
# Определяет формат файла, архитектуру и тип исполняемого файла.
# Ожидаемо: ELF, script, архитектура и dynamic/static linking.
file <program>

# Показывает первую строку скрипта вместе со скрытыми символами.
# Ожидаемо: shebang; символ ^M укажет на CRLF.
head -n 1 <program> | cat -A

# Показывает динамические библиотеки или отсутствующие зависимости.
# Ожидаемо: пути библиотек либо строки not found.
ldd <program>

# Показывает ELF interpreter, который должен существовать в системе.
# Ожидаемо: Requesting program interpreter с путём к ld-linux.
readelf -l <program> | grep interpreter
```
