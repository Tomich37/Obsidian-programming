# Что делать если место есть но файл не создается

[[00 Файловые системы]]

Если `df -h` показывает свободное место, но файл не создается, надо проверить не только место.

Частые причины:
- закончились inode;
- нет прав на директорию;
- файловая система смонтирована read-only;
- сработала quota;
- достигнут лимит открытых файлов;
- проблема с сетевой ФС;
- директория или путь не существуют.

Проверки:
```bash
# Показывает свободное место на файловых системах.
# Ожидаемо: если Use% не 100%, место в байтах еще есть.
df -h

# Показывает использование inode.
# Ожидаемо: если IUse% = 100%, новые файлы создать нельзя.
df -i

# Ищет файловые системы, смонтированные только для чтения.
# Ожидаемо: строки с ro, если какая-то ФС в read-only режиме.
mount | grep ' ro,'

# Проверяет, можно ли создать файл в текущей директории.
# Ожидаемо: файл testfile появится или команда покажет ошибку прав/ФС.
touch testfile

# Показывает права текущей директории.
# Ожидаемо: права, владелец и группа; нужна запись для создания файлов.
ls -ld .

# Показывает лимит открытых файлов для текущей shell-сессии.
# Ожидаемо: число вроде 1024/4096/65535.
ulimit -n

# Показывает дисковые квоты пользователя, если quota включена.
# Ожидаемо: лимиты и использование или сообщение, что quota не настроена.
quota -s
```

Если закончились inode:

Это значит, что создано слишком много мелких файлов. Место в гигабайтах еще есть, но новых файлов создать нельзя, потому что закончились записи inode.

Короткий ответ:

Сначала проверил бы inode через `df -i`, потом права, режим монтирования, quota и лимиты процесса. Свободное место по `df -h` не гарантирует, что файл можно создать.
