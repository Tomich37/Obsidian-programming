# Ограничение ресурсов контейнера

[[00 Docker]]

Контейнер можно ограничить по CPU, памяти и блочному I/O через cgroups. Скорость сети обычно ограничивают не параметром Docker, а средствами Linux traffic control (`tc`), CNI-плагином или политиками платформы-оркестратора.

Команды:
```bash
# Запускает контейнер с лимитом памяти 512 MB.
# Ожидаемо: контейнер не сможет использовать больше заданного лимита.
docker run --memory=512m nginx

# Запускает контейнер с ограничением CPU.
# Ожидаемо: контейнер будет использовать примерно до половины CPU.
docker run --cpus=0.5 nginx

# Показывает текущее потребление ресурсов контейнерами.
# Ожидаемо: CPU %, memory usage/limit и I/O.
docker stats

# Ограничивает относительный вес записи на блочное устройство.
# Ожидаемо: при конкуренции контейнер с меньшим весом получит меньшую долю I/O.
docker run --blkio-weight 200 nginx

# Показывает cgroup-настройки CPU, памяти и блочного I/O контейнера.
# Ожидаемо: числовые лимиты, веса и ограничения устройств в HostConfig.
docker inspect --format '{{json .HostConfig}}' <container>
```

Что важно:

Если контейнер превысит memory limit, его может убить OOM killer. В Kubernetes это часто видно как `OOMKilled`.

Короткий ответ:

Ограничения Docker работают через cgroups. CPU можно ограничить квотой или весом, превышение memory limit может привести к OOM, а блочный I/O - ограничить весом или скоростью для конкретного устройства. Сеть ограничивают на уровне Linux или оркестратора.
