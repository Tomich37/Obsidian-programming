# Multi-stage build

[[00 Инструкции Dockerfile]]

Multi-stage build позволяет использовать несколько стадий сборки в одном Dockerfile.

Зачем нужно:
- собрать приложение в одном образе;
- перенести только готовый бинарник/артефакт в runtime-образ;
- уменьшить размер финального образа;
- не тащить компиляторы и build-зависимости в production.

Пример:
```Dockerfile
# Стадия сборки: берем Go-образ с компилятором и называем стадию build.
FROM golang:1.22 AS build
# Рабочая директория внутри сборочного контейнера.
WORKDIR /src
# Копируем исходники проекта в сборочный образ.
COPY . .
# Собираем бинарник app; ожидаемо: появится файл /src/app.
RUN go build -o app

# Финальная стадия: берем маленький runtime-образ без компилятора.
FROM alpine:3.20
# Забираем только готовый бинарник из стадии build.
COPY --from=build /src/app /app
# При запуске контейнера выполняется готовое приложение.
ENTRYPOINT ["/app"]
```

Короткий ответ:

Multi-stage build отделяет сборочную среду от runtime. Финальный образ получается меньше и чище.
