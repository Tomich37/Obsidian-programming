# Оптимизация Docker-образов

[[00 Docker]]

Основные способы уменьшить образ и ускорить сборку:
- выбрать небольшой, но поддерживаемый базовый образ;
- использовать multi-stage build и копировать только runtime-артефакты;
- добавить `.dockerignore`;
- сначала копировать lock-файлы зависимостей, затем код;
- объединять установку и очистку package cache в одном `RUN`;
- не добавлять компиляторы и тестовые данные в финальный stage;
- проверять крупные слои через `docker history`.

`RUN`, `COPY` и `ADD` создают filesystem layers; metadata-инструкции тоже остаются в истории образа. Большое число слоёв не всегда главная проблема: важнее их содержимое и возможность кеширования.

Squash объединяет слои, но ухудшает повторное использование кеша и скрывает историю. Обычно multi-stage build и корректный порядок инструкций предпочтительнее.

```bash
# Показывает размер и команду каждого слоя образа.
# Ожидаемо: таблица IMAGE, CREATED BY и SIZE, по которой видны тяжёлые слои.
docker history --no-trunc <image>

# Собирает образ с подробным выводом BuildKit.
# Ожидаемо: этапы сборки, cache hit/miss и размер передаваемого build context.
docker build --progress=plain -t <image>:<tag> .
```
