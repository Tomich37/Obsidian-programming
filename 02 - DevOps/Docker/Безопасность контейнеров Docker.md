# Безопасность контейнеров Docker

[[00 Docker]]

Если в образе не задана инструкция `USER`, процесс контейнера обычно запускается от `root`. Это root внутри user namespace, но без дополнительных настроек он может иметь опасные возможности относительно ядра и смонтированных ресурсов хоста.

Риски:
- запись в bind mount с правами root;
- эксплуатация уязвимости общего ядра;
- лишние Linux capabilities;
- доступ к Docker socket фактически даёт контроль над Docker host.

Базовые меры:
- создать непривилегированного пользователя и задать `USER`;
- не использовать `--privileged` без необходимости;
- убирать capabilities и добавлять только нужные;
- использовать read-only root filesystem и ограниченные mounts;
- задавать seccomp, AppArmor/SELinux и лимиты ресурсов;
- фиксировать версии образов и регулярно сканировать зависимости.

```bash
# Показывает пользователя, заданного в конфигурации образа или контейнера.
# Ожидаемо: имя/UID; пустая строка обычно означает пользователя root по умолчанию.
docker inspect --format '{{.Config.User}}' <image-or-container>

# Показывает эффективные capabilities процесса внутри контейнера.
# Ожидаемо: набор CapEff, который можно декодировать утилитой capsh.
docker exec <container> grep CapEff /proc/1/status
```
