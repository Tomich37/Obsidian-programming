# Как диагностировать контейнер

[[00 Docker]]

Диагностику контейнера начинаю со статуса, логов, ресурсов и входа внутрь.

Команды:
```bash
# Показывает запущенные контейнеры.
# Ожидаемо: статус Up или Restarting, порты и имя контейнера.
docker ps

# Показывает все контейнеры, включая упавшие.
# Ожидаемо: можно увидеть Exited и код завершения.
docker ps -a

# Показывает логи контейнера.
# Ожидаемо: stdout/stderr приложения.
docker logs <container>

# Показывает потребление ресурсов контейнером.
# Ожидаемо: CPU %, memory usage, network I/O, block I/O.
docker stats <container>

# Запускает shell внутри контейнера.
# Ожидаемо: интерактивная командная строка внутри контейнера, если bash есть.
docker exec -it <container> bash

# Показывает подробную JSON-информацию о контейнере.
# Ожидаемо: env, mounts, network, state, restart count.
docker inspect <container>
```

Короткий ответ:

Сначала смотрю `docker ps -a`, потом `logs`, `stats`, `inspect`; если нужно, захожу через `exec`.
