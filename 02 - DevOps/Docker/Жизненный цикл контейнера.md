# Жизненный цикл контейнера

[[00 Docker]]

Контейнер работает, пока жив его основной процесс PID 1.

- `docker stop` отправляет PID 1 сигнал `SIGTERM`, ждёт grace period и затем отправляет `SIGKILL`;
- `docker kill` по умолчанию сразу отправляет `SIGKILL`, но сигнал можно выбрать;
- `docker pause` замораживает процессы через механизм cgroup freezer и не завершает их;
- завершение PID 1 изнутри останавливает контейнер;
- restart policy может автоматически поднять контейнер после сбоя или рестарта Docker daemon.

```bash
# Показывает статус, основной PID на хосте и restart policy контейнера.
# Ожидаемо: running/exited, числовой PID и policy no/always/on-failure/unless-stopped.
docker inspect --format 'status={{.State.Status}} pid={{.State.Pid}} restart={{.HostConfig.RestartPolicy.Name}}' <container>

# Корректно останавливает контейнер, давая приложению 30 секунд на завершение.
# Ожидаемо: имя контейнера после успешной остановки; затем статус exited.
docker stop --time 30 <container>

# Приостанавливает все процессы без завершения контейнера.
# Ожидаемо: статус paused в docker ps.
docker pause <container>
```

Для корректной остановки приложение должно обрабатывать `SIGTERM`, а shell-entrypoint должен передавать сигналы через `exec`.
