# stdout stderr stdin и перенаправления

[[00 Основы Bash]]

В Linux у процесса есть стандартные потоки:
- `stdin` - ввод, file descriptor 0;
- `stdout` - обычный вывод, file descriptor 1;
- `stderr` - ошибки, file descriptor 2.

Примеры:
```bash
# Перенаправляет обычный вывод в файл.
# Ожидаемо: stdout попадет в out.log, ошибки останутся на экране.
command > out.log

# Перенаправляет ошибки в файл.
# Ожидаемо: stderr попадет в err.log, обычный вывод останется на экране.
command 2> err.log

# Отбрасывает обычный вывод, оставляя ошибки на экране.
# Ожидаемо: stdout исчезнет, stderr будет виден.
command > /dev/null

# Отбрасывает обычный вывод и ошибки.
# Ожидаемо: на экране ничего не будет, даже если команда пишет ошибки.
command > /dev/null 2>&1

# Передает stdout первой команды на stdin второй.
# Ожидаемо: command2 обработает обычный вывод command1.
command1 | command2
```

Короткий ответ:

Pipe передает только stdout. Ошибки идут в stderr отдельно, поэтому для них нужен `2>`, `2>&1` или отдельная обработка.
