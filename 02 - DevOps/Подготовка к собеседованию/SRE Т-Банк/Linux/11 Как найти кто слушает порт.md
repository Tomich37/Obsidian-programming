# Как найти кто слушает порт

[[00 Linux - вопросы]]

Основная команда:
```bash
# Показывает слушающие TCP/UDP-порты и процессы.
# Ожидаемо: локальный адрес, порт, PID и имя процесса.
ss -tulnp
```

Что значат ключи:
- `-t` - TCP;
- `-u` - UDP;
- `-l` - listening;
- `-n` - не резолвить имена;
- `-p` - показать процесс.

Пример:
```bash
# Фильтрует список слушающих портов по 443.
# Ожидаемо: строка процесса, который слушает HTTPS-порт, если такой есть.
ss -tulnp | grep ':443'
```

Альтернативы:
```bash
# Показывает процесс, который использует порт 443.
# Ожидаемо: COMMAND, PID, USER и сетевое соединение.
lsof -i :443

# Старый аналог ss для просмотра слушающих портов.
# Ожидаемо: список TCP/UDP-портов и PID процессов, если netstat установлен.
netstat -tulnp
```

Если порт занят:
1. Найти PID.
2. Проверить процесс.
3. Понять, должен ли он слушать этот порт.
4. Не убивать процесс вслепую, особенно на production.

Короткий ответ:

Я бы использовал `ss -tulnp`, нашел PID и команду процесса, а потом проверил сервис через `systemctl status` или `ps`.
