# Как Linux управляет памятью

[[00 Linux - вопросы]]

Linux использует оперативную память не только под процессы, но и под кеш файловой системы. Поэтому высокая занятость RAM сама по себе не всегда проблема.

Основные области:
- `used` - память, занятая процессами и ядром;
- `free` - полностью свободная память;
- `buff/cache` - буферы и файловый кеш;
- `available` - память, которую система может отдать новым процессам без сильной деградации;
- `swap` - область на диске для выгрузки страниц памяти.

Что важно:

Если `free` мало, но `available` достаточно - обычно все нормально. Linux просто использует память эффективно под кеш.

Проблема начинается, когда:
- мало `available`;
- активно растет `swap`;
- процессы получают OOM;
- приложение начинает тормозить из-за нехватки памяти.

Команды:
```bash
# Показывает использование RAM и swap в человекочитаемом виде.
# Ожидаемо: total, used, free, buff/cache, available, swap.
free -h

# Каждую секунду показывает CPU, память, swap и I/O.
# Ожидаемо: динамика si/so для swap, free memory, us/sy/id/wa по CPU.
vmstat 1

# Интерактивно показывает процессы и потребление CPU/RAM.
# Ожидаемо: сверху общая память, ниже процессы с %CPU и %MEM.
top

# Более удобная интерактивная версия top.
# Ожидаемо: цветные шкалы CPU/Mem/Swap и список процессов.
htop

# Ищет в сообщениях ядра события OOM.
# Ожидаемо: строки про killed process, если ядро убивало процесс из-за памяти.
dmesg | grep -i oom
```

Короткий ответ:

Linux старается не держать память пустой: свободная память используется под кеш, который можно быстро освободить. Поэтому смотреть нужно не только `used`, но и `available`, swap и признаки OOM.
