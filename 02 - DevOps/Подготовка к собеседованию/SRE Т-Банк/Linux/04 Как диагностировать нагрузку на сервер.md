# Как диагностировать нагрузку на сервер

[[00 Linux - вопросы]]

Диагностику лучше делать по слоям: CPU, память, диск, сеть, процессы и логи.

Базовый порядок:
1. Проверить общую картину:
```bash
# Показывает uptime, количество пользователей и Load Average.
# Ожидаемо: три числа LA за 1, 5 и 15 минут.
uptime

# Интерактивно показывает процессы и общую загрузку CPU/RAM.
# Ожидаемо: сверху CPU, memory, load average, ниже процессы.
top

# Более удобный интерактивный монитор процессов.
# Ожидаемо: цветные шкалы ресурсов и сортировка процессов.
htop
```

2. Проверить память:
```bash
# Показывает использование RAM и swap.
# Ожидаемо: total/used/free/available и занятость swap.
free -h

# Каждую секунду показывает память, CPU, swap и I/O.
# Ожидаемо: если si/so больше 0, система активно использует swap.
vmstat 1
```

3. Проверить диск:
```bash
# Показывает свободное место на файловых системах.
# Ожидаемо: размер, занято, доступно, процент использования.
df -h

# Показывает использование inode.
# Ожидаемо: если IUse% близко к 100%, новые файлы могут не создаваться.
df -i

# Показывает расширенную статистику дисков каждые 2 секунды, всего 3 раза.
# Ожидаемо: await, r/s, w/s, %util для поиска перегруженного диска.
iostat -x 2 3

# Интерактивно показывает процессы, которые генерируют дисковый I/O.
# Ожидаемо: список процессов с чтением/записью в реальном времени.
iotop
```

4. Проверить сеть:
```bash
# Показывает слушающие TCP/UDP-порты и процессы.
# Ожидаемо: адреса вида 0.0.0.0:80 или 127.0.0.1:5432 и PID процесса.
ss -tulnp

# Показывает IP-адреса сетевых интерфейсов.
# Ожидаемо: список интерфейсов, их состояние UP/DOWN и IP-адреса.
ip a

# Показывает таблицу маршрутизации.
# Ожидаемо: default route через шлюз и маршруты до локальных сетей.
ip route
```

5. Проверить сервис:
```bash
# Показывает состояние systemd-сервиса.
# Ожидаемо: active/running или failed, PID, последние строки логов.
systemctl status <service>

# Показывает логи сервиса в реальном времени.
# Ожидаемо: новые строки журнала по мере работы сервиса.
journalctl -u <service> -f
```

Что смотреть:
- `Load Average` относительно числа CPU;
- `%CPU` и `%MEM` у процессов;
- `iowait`, если сервер ждет диск;
- `swap`, если не хватает RAM;
- ошибки в логах;
- занятость inode через `df -i`.

Короткий ответ:

Я бы начал с `top/htop` и `uptime`, потом разделил проблему: CPU, память, диск, сеть или конкретный сервис. После этого смотрел бы логи и метрики, чтобы подтвердить гипотезу.
