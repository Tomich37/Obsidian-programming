# Краткое
| Уровень                                 | Что отвечает              | Типичные проблемы                                           | Полезные команды/инструменты                                                            |
| --------------------------------------- | ------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **7. Прикладной (Application)**         | HTTP, DNS, SMTP, REST API | `curl` выдаёт 500, DNS не резолвится, API не отвечает       | `curl`, `dig`, `nslookup`, `http`, логи приложений                                      |
| **6. Представительский (Presentation)** | SSL/TLS, кодировки        | Ошибки `SSL certificate verify failed`, `handshake failure` | `openssl s_client -connect host:443`, проверка cert-manager, проверка `ca-certificates` |
| **5. Сеансовый (Session)**              | Сессии, VPN, SSH          | Обрывы SSH, таймауты при VPN                                | `ssh -v user@host`, `tmux/screen`, VPN-логи                                             |
| **4. Транспортный (Transport)**         | TCP, UDP, порты           | Порт занят, сервис не слушает, UDP пакеты теряются          | `ss -lntup`, `netstat -tulnp`, `nc -vz host port`, `telnet host port`                   |
| **3. Сетевой (Network)**                | IP, маршрутизация, ICMP   | Нет маршрута, пинги не идут, NAT не настроен                | `ping`, `traceroute`, `ip route show`, `iptables -L -n`                                 |
| **2. Канальный (Data Link)**            | MAC-адреса, Ethernet, ARP | ARP не резолвит, мост Docker не работает, VLAN не настроен  | `arp -a`, `ip link`, `brctl show`, `tcpdump -e`                                         |
| **1. Физический (Physical)**            | Кабели, радио, линк       | Нет линка, кабель выдернут, порт выключен                   | `ethtool eth0`, `dmesg`                                                                 |
## Как пользоваться шпаргалкой
1. **Идём сверху вниз**:    
    - Если `curl http://service:8080/healthz` не отвечает → проверяем 4 уровень (порт слушает?).        
    - Если порта нет → проверяем 3 уровень (IP маршрутизация).        
    - Если IP пингуется, но API не работает → 7 уровень.        
2. **Docker/Kubernetes контекст**:    
    - Межконтейнерные сети → 2–3 уровень.        
    - Service/Ingress → 4/7 уровни.        
    - TLS-сертификаты в ingress → 6 уровень.        
3. **DevOps workflow**:    
    - VPN для CI/CD → 3–5 уровни.        
    - SSL в GitLab Runner → 6 уровень.        
    - Мониторинг (Prometheus, Grafana) → 7 уровень.
# Подробное
### **1. Физический уровень (Physical)**

- **Что это:** провода, оптоволокно, радиосигналы, электрические импульсы.    
- **DevOps:** напрямую редко работает, но важно понимать для диагностики: кабель/порт может быть банальной причиной недоступности контейнера или сервера.    
- **Инструменты:** ping с ошибкой _destination unreachable_, проверка линков в `ethtool`, работа в облаке (виртуальная «физика»).   
---
### **2. Канальный уровень (Data Link)**
- **Что это:** MAC-адреса, Ethernet, ARP.    
- **DevOps:** важно при работе с Docker/Kubernetes сетями, VLAN, настройке бриджей, туннелей.    
- **Пример:** контейнер не пингуется, потому что ARP-таблица не обновилась.    
- **Инструменты:** `arp -a`, `brctl show`, `ip link`.    
---
### **3. Сетевой уровень (Network)**
- **Что это:** IP-адреса, маршрутизация, ICMP.    
- **DevOps:** нужно уметь маршрутизировать трафик между контейнерами, VM и внешней сетью.    
- **Пример:** контейнер имеет IP 172.18.0.2, но не видно из VM → нет маршрута.    
- **Инструменты:** `ip route`, `traceroute`, `iptables`/`nftables`.    
---
### **4. Транспортный уровень (Transport)**
- **Что это:** TCP, UDP, порты.    
- **DevOps:** разруливает проблемы «порт занят», «сервис не слушает».    
- **Пример:** приложение крутится, но порт 8080 закрыт в Docker → не видно из вне.    
- **Инструменты:** `netstat -tulnp`, `ss -lnt`, `telnet host port`, `nc`.    
---
### **5. Сеансовый уровень (Session)**
- **Что это:** установление/поддержка соединений.    
- **DevOps:** чаще видим в контексте SSH-сессий, VPN, прокси.    
- **Пример:** сессия SSH рвётся — надо разбираться, TCP или выше?    
- **Инструменты:** `tmux`, `ssh -v`, конфиги VPN.    
---
### **6. Представительский уровень (Presentation)**
- **Что это:** кодировки, шифрование, SSL/TLS.    
- **DevOps:** настройка HTTPS, сертификатов, шифрование логов, API-гейтов.    
- **Пример:** «certificate verify failed» при curl к API.    
- **Инструменты:** `openssl s_client`, `keytool`, cert-manager в Kubernetes.    
---
### **7. Прикладной уровень (Application)**
- **Что это:** HTTP, FTP, DNS, SMTP, REST API.    
- **DevOps:** тут мы чаще всего работаем — деплой приложений, настройка балансировщиков, работа с API.    
- **Пример:** `curl http://service:8080/healthz` не отвечает → надо проверить уровни ниже.    
- **Инструменты:** `curl`, `dig`, `nslookup`, `httpie`.    
---
## Как это полезно DevOps'у?
1. **Диагностика проблем**  
    Если сервис не работает → идём сверху вниз:    
    - HTTP 500? → приложение.        
    - Нет соединения? → TCP/UDP.        
    - Не пингуется? → IP.        
    - Нет ARP? → канальный.        
    - Линка нет? → физика.        
2. **Docker/Kubernetes**    
    - Контейнеры общаются через виртуальные мосты → уровни 2–3.        
    - Service Mesh (Istio) работает на уровне 7.        
    - LoadBalancer → уровень 4/7.        
3. **CI/CD и инфраструктура**    
    - Настройка VPN → 3–5 уровни.        
    - Мониторинг трафика → 3–7.        
    - SSL/TLS сертификаты → уровень 6.
