# Что такое 502 503 504

[[00 Протоколы]]

Эти ошибки часто встречаются за reverse proxy или балансировщиком.

`502 Bad Gateway` - прокси получил некорректный ответ от upstream.

Причины:
- backend упал;
- backend закрыл соединение;
- ошибка протокола;
- неправильный upstream.

`503 Service Unavailable` - сервис недоступен.

Причины:
- нет живых backend'ов;
- сервис перегружен;
- maintenance;
- лимиты на балансировщике.

`504 Gateway Timeout` - прокси не дождался ответа от upstream.

Причины:
- backend отвечает слишком долго;
- проблема с сетью;
- тяжелый запрос;
- неправильные timeout'ы.

# Как диагностировать 502

1. Определить, какой proxy вернул ошибку, и найти соответствующую запись в access/error log.
2. Проверить, есть ли живые upstream-адреса и правильно ли настроены host, port и протокол.
3. С proxy-хоста обратиться к upstream напрямую, исключив внешний DNS и балансировщик.
4. Проверить состояние backend, его логи, прослушиваемый socket, TLS/SNI и сетевые таймауты.
5. Сопоставить время ошибки с рестартами, OOM, исчерпанием соединений и ростом latency.

```bash
# Проверяет ответ upstream напрямую с proxy-хоста и показывает HTTP-заголовки.
# Ожидаемо: код backend или ошибка соединения/TLS, позволяющая локализовать 502.
curl -vk --connect-timeout 3 http://<upstream>:<port>/health

# Показывает, слушает ли backend ожидаемый TCP-порт и какой процесс им владеет.
# Ожидаемо: строка LISTEN с адресом, портом и PID либо пустой вывод.
ss -ltnp | grep ':<port>'

# Показывает последние сообщения reverse proxy.
# Ожидаемо: причины вроде connection refused, upstream reset или timeout.
journalctl -u <proxy-service> -n 100 --no-pager
```

Короткий ответ:

502 - proxy не смог получить корректный ответ от backend, 503 - сервис недоступен, 504 - истек timeout ожидания backend. Для 502 сначала проверяю error log proxy, затем доступ к upstream напрямую и состояние backend.
