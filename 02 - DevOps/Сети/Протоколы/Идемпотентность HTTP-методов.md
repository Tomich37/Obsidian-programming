# Идемпотентность HTTP методов

[[00 Протоколы]]

Идемпотентность означает, что повторение одного и того же запроса дает тот же итоговый результат.

Идемпотентные методы:
- `GET`;
- `PUT`;
- `DELETE`;
- `HEAD`;
- `OPTIONS`.

Неидемпотентный обычно:
- `POST`.

Пример:

`DELETE /users/10` можно повторить несколько раз. Итог один - пользователя нет.

`POST /orders` при повторе может создать два заказа, если не использовать idempotency key.

Почему важно для SRE:

При сетевых сбоях клиент может повторять запрос. Если операция неидемпотентна, retry может создать дубли или испортить данные.

Короткий ответ:

Идемпотентный запрос можно безопасно повторять с тем же итоговым состоянием. Это важно для retry и устойчивости распределенных систем.
