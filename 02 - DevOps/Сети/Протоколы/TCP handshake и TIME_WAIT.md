# Что такое TCP handshake и TIME WAIT

[[00 Протоколы]]

TCP-соединение устанавливается через three-way handshake:
1. Клиент отправляет `SYN`.
2. Сервер отвечает `SYN-ACK`.
3. Клиент отправляет `ACK`.

После этого стороны могут передавать данные.

TCP поддерживает надёжное соединение с помощью sequence numbers, acknowledgement, checksum, retransmission, sliding window и congestion control. Сам факт отсутствия трафика не гарантирует живое соединение: состояние проверяют прикладными heartbeat или TCP keepalive с подходящими таймерами.

`TIME_WAIT` - состояние TCP-сокета после закрытия соединения. Оно нужно, чтобы:
- старые пакеты не попали в новое соединение;
- была возможность повторно отправить финальный ACK.

Почему важно для SRE:

Если приложение создает слишком много коротких соединений, может быть много `TIME_WAIT`, исчерпание ephemeral ports или нагрузка на сеть.

Команды:
```bash
# Показывает все TCP-соединения и их состояния.
# Ожидаемо: LISTEN, ESTAB, TIME-WAIT, CLOSE-WAIT и другие состояния.
ss -tan

# Показывает только TCP-соединения в TIME-WAIT.
# Ожидаемо: список недавно закрытых соединений, ожидающих безопасного завершения.
ss -tan state time-wait

# Показывает TCP keepalive и другие параметры конкретного сокета.
# Ожидаемо: timer и внутреннее состояние сокета; требуется актуальная версия ss.
ss -toan
```

Короткий ответ:

Handshake нужен для установки TCP-соединения, а `TIME_WAIT` - нормальное состояние после закрытия, которое защищает от проблем со старыми пакетами.
