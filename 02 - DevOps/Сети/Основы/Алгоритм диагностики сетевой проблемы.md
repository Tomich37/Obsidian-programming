# Как диагностировать сетевую проблему

[[00 Основы сетей]]

Диагностику сети удобно делать от простого к сложному.

1. Проверить IP и маршрут:
```bash
# Показывает адреса и состояние сетевых интерфейсов.
# Ожидаемо: видно, есть ли IP-адрес и поднят ли интерфейс.
ip a

# Показывает маршруты, включая маршрут по умолчанию.
# Ожидаемо: строка default via <gateway>, если есть выход в другие сети.
ip route
```

2. Проверить доступность хоста:
```bash
# Проверяет базовую сетевую доступность через ICMP.
# Ожидаемо: ответы с временем latency или потери пакетов/timeout.
ping <host>
```

3. Проверить маршрут:
```bash
# Показывает маршрут до хоста по промежуточным узлам.
# Ожидаемо: список hop'ов и задержек, либо место, где маршрут обрывается.
traceroute <host>
```

4. Проверить DNS:
```bash
# Запрашивает DNS-записи домена.
# Ожидаемо: IP-адреса, DNS-сервер, время ответа и секция ANSWER.
dig example.com

# Более простой DNS-запрос имени.
# Ожидаемо: адрес DNS-сервера и IP-адрес домена.
nslookup example.com
```

5. Проверить порт:
```bash
# Проверяет, открыт ли TCP-порт на удаленном хосте.
# Ожидаемо: succeeded/open при доступном порте или refused/timeout при проблеме.
nc -vz <host> <port>

# Старый способ проверить TCP-подключение к порту.
# Ожидаемо: подключение к порту или ошибка connection refused/timeout.
telnet <host> <port>
```

6. Проверить локальные слушающие порты:
```bash
# Показывает локальные слушающие TCP/UDP-порты и процессы.
# Ожидаемо: адрес, порт, PID и имя процесса.
ss -tulnp
```

7. Проверить HTTP:
```bash
# Делает HTTP/HTTPS-запрос с подробным выводом.
# Ожидаемо: DNS, TCP/TLS handshake, HTTP-статус, заголовки и ошибки.
curl -v https://example.com
```

Короткий ответ:

Я бы проверял по слоям: есть ли IP, есть ли маршрут, резолвится ли DNS, доступен ли хост, открыт ли порт, отвечает ли приложение.
