# Readiness, liveness и startup probes

[[00 Глоссарий]]

- `readinessProbe` отвечает, можно ли направлять трафик в контейнер. Ошибка убирает Pod из EndpointSlice, но не перезапускает контейнер.
- `livenessProbe` проверяет, не зависло ли приложение. Повторные ошибки приводят к перезапуску контейнера kubelet.
- `startupProbe` даёт медленно стартующему приложению время на запуск. Пока она не успешна, liveness и readiness не выполняются.

Проба может использовать HTTP GET, TCP socket, gRPC или exec. Пробы проверяют разные свойства, поэтому один и тот же endpoint не всегда подходит для всех трёх.

```yaml
# Startup допускает до 150 секунд запуска, затем включаются остальные проверки.
# Ожидаемо: Pod не будет преждевременно перезапущен во время долгого старта.
startupProbe:
  httpGet:
    path: /startup
    port: 8080
  failureThreshold: 30
  periodSeconds: 5

# Readiness управляет включением Pod в балансировку Service.
# Ожидаемо: при неуспехе Pod останется запущенным, но перестанет получать трафик.
readinessProbe:
  httpGet:
    path: /ready
    port: 8080

# Liveness перезапускает зависший контейнер после повторных ошибок.
# Ожидаемо: kubelet увеличит restartCount контейнера при устойчивом сбое.
livenessProbe:
  httpGet:
    path: /live
    port: 8080
```
