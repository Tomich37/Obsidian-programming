Манифест — это **YAML-файл**, который описывает объект Kubernetes (Pod, Deployment, Service и т.д.).  
Он говорит Kubernetes: _«создай вот такой объект с такими параметрами»_.
# Базовая структура
```yaml
apiVersion: v1    # Версия API (зависит отресурса)
kind: Pod         # Тип оъекта (Pod, Service, Deployment, ...)
metadata:         # Метаданные - имя, метки, аннотации
	name: my-pod
	labels:
		app: test
spec:             # Спецификация (что именно создать)
	containers:
		- name: nginx
		  image: nginx:latest
```
- `apiVersion` — говорит, какой API использовать (например, `v1`, `apps/v1`, `batch/v1`).    
- `kind` — тип объекта (Pod, Deployment, Service, ConfigMap, Secret и др.).    
- `metadata` — имя, namespace, labels (метки для селектора).    
- `spec` — самое главное: _описание того, что должен делать Kubernetes_.
## Примеры разных kind
- **Pod** → минимальный объект, запускает контейнер.    
- **Deployment** → управляет подами, следит за количеством реплик.    
- **Service** → сетевой доступ к подам.    
- **ConfigMap** → хранит конфигурации.    
- **Secret** → хранит пароли/ключи (в base64).
# Важные поля внутри `spec`
## Для Pod
Минимальная единица запуска (контейнер)
```yaml
spec:
	containers:
		- name: nginx
		  image: nginx:1.25
		  ports:
			  - containerPort: 80
		  env:                       # Переменные окружения
			  - name: MODE
			    value: "production"
		  volumeMounts:              # Подключение томов
			  - name: config
			    mountPath: /etc/config
	volumes:                         # Сами тома
		- name: config
		  configMap:
			  name: my-config
```
Поля в `spec`:
- `containers` → список контейнеров (name, image, ports, env, volumeMounts).    
- `volumes` → подключение ConfigMap, Secret, PVC.
## Для Deployment
Следит за количеством реплик, перезапускает поды.
```yaml
apiVersion: apps/v1
spec:
	replicas: 3         # Сколько подов держать
	selector:
		matchLabels:
			app: nginx
	template:           # Шаблон пода
		metadata:
			labels:
				app: nginx
		spec:
			containers:
				- name: nginx
				  image: nginx:latest	
```
Поля в `spec`:
- `replicas` → сколько подов держать.    
- `selector` + `template.metadata.labels` → связывают деплоймент с подами.    
- `template.spec` → это как Pod внутри.
## Для Service
Сетевой доступ к подам.
```yaml
apiVersion: v1
kind: Service                  # тип (ClusterIP, NodePort, LoadBalancer)
metadata:
  name: backend-service
spec:
  type: ClusterIP
  selector:
    app: backend
  ports:
    - port: 80
      targetPort: 5000

```
Типы сервисов:
- `ClusterIP` (по умолчанию) → доступ только внутри кластера.    
- `NodePort` → доступ снаружи через `<NodeIP>:<NodePort>`.    
- `LoadBalancer` → для облаков, выдаёт внешний IP.
## ConfigMap
Хранит конфигурацию.
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
	name: my-config
data:
	MODE: "production"
	TIMEOUT: "30"
```

Используется в pod:
```yaml
envFrom:
	- configMapRef:
	  name: my-config
```
## Secret
Хранит чувствительные данные (пароли, токены).
```yaml
apiVersion: v1
kind: Secret
metadata:
	name: my-secret
type: Opaque
data:
	PASSWORD: cGFzc3dvcmQ=   # base64 от "password"
```
