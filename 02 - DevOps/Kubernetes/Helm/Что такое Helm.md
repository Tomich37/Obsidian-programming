**Helm** — это менеджер пакетов для Kubernetes. Если вы знакомы с такими менеджерами пакетов, как `apt` для Ubuntu, `yum` для CentOS, `npm` для Node.js или `pip` для Python, то концепция будет вам очень знакома.

Проще говоря, **Helm — это инструмент, который помогает вам устанавливать, настраивать, обновлять и управлять приложениями в Kubernetes.**

Без Helm управление приложениями в K8s выглядело бы так:

- У вас есть множество YAML-файлов: Deployment, Service, ConfigMap, Secret, Ingress и т.д.    
- Вам нужно применять их все по порядок с помощью `kubectl apply -f ...`.    
- Для каждого нового окружения (dev, stage, prod) вам нужно создавать и поддерживать отдельные наборы этих файлов, меняя в них параметры (например, имена, метки, образы контейнеров, переменные среды).    
- Это быстро становится рутинным, сложным и подверженным ошибкам.    
### Основная проблема, которую решает Helm
Управление сложными приложениями в Kubernetes. Многие приложения состоят из нескольких компонентов (например, веб-сервер, база данных, кеш, миграции), каждый из которых требует свой набор YAML-манифестов. Ручное развертывание и управление такими наборами файлов — это администрирование "в лоб", которое плохо масштабируется.

### Ключевые концепции Helm
Чтобы понять, как работает Helm, нужно знать две основные сущности:
1. **Chart (Чарт)**    
    - Это **пакет** Helm. Его можно сравнить с `.deb` или `.rpm` пакетом в Linux.        
    - Чарт — это коллекция файлов, которая описывает связанный набор ресурсов Kubernetes. Он содержит все необходимые YAML-манифесты, а также специальные файлы для их настройки.        
    - Чарты упаковываются в специальные архивы (`.tgz`).        
    - Структура чарта:        
```text        
my-app-chart/
├── Chart.yaml          # Метаинформация о чарте (имя, версия, описание)
├── values.yaml         # Значения по умолчанию для конфигурации
├── templates/          # Директория с шаблонами YAML-манифестов
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
└── charts/             # Директория для зависимостей (подчиненных чартов)
```        
2. **Release (Релиз)**    
    - Это **экземпляр приложения**, развернутый в Kubernetes с помощью конкретного чарта.        
    - Если чарт — это _программа установки_ (например, `setup.exe`), то релиз — это _установленная программа_ (например, "Google Chrome, версия 120, установленный на моем компьютере").        
    - Один и тот же чарт можно использовать для установки множества различных релизов в одном кластере. Например, вы можете установить два релиза одной и той же базы данных: `my-database-dev` и `my-database-prod` с разными конфигурациями.
3. **Repository (Репозиторий)**    
    - Это место, где хранятся и публикуются чарты. Его можно сравнить с Docker Hub, но для чартов Helm.        
    - Самый популярный публичный репозиторий — [Artifact Hub](https://artifacthub.io/).        

### Как работает Helm? Шаблонизация и значения (Templating & Values)
Самое мощное свойство Helm — это **шаблонизация**.
- Файлы в директории `templates/` — это не просто YAML-файлы, а шаблоны на языке Go templates.    
- В эти шаблоны можно вставлять переменные и использовать конструкции (условия, циклы).    
- Параметры для этих шаблонов хранятся в файле `values.yaml`.    

**Простой пример:**  
В вашем `deployment.yaml` шаблоне может быть такая строка:
```yaml
image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
```
А в файле `values.yaml` вы задаете значения по умолчанию:
```yaml
image:
  repository: nginx
  tag: "1.25.3"
```
Когда вы устанавливаете чарт, Helm берет шаблоны, подставляет в них значения из `values.yaml`, генерирует готовые YAML-манифесты и отправляет их в API Kubernetes.

**Вы можете переопределять значения из `values.yaml` во время установки:**
```bash
helm install my-nginx . --set image.tag=1.24.0
```
Эта команда установит релиз `my-nginx` из чарта в текущей директории, но с образом `nginx:1.24.0` вместо версии по умолчанию.

### Зачем нужен Helm? Преимущества
1. **Повторное использование (Reusability):** Один чарт можно использовать для развертывания в разных окружениях (dev, prod), просто меняя параметры в `values.yaml`.
2. **Простота управления:** Одна команда устанавливает или обновляет сложное приложение из десятков манифестов.    
3. **Версионирование:** Чарты имеют версии, что позволяет контролировать, какая версия приложения развернута в кластере. Helm также хранит историю развертываний каждого релиза, что позволяет легко откатиться на предыдущую версию (`helm rollback`).    
4. **Публичные чарты:** Можно легко установить популярное приложение (например, Grafana, PostgreSQL, Redis) одной командой: `helm install my-postgres bitnami/postgresql`. Это избавляет от необходимости искать и править YAML-манифесты вручную.    
5. **Согласованность:** Стандартизирует процесс развертывания приложений в команде.
