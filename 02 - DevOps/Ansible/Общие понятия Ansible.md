# Общие понятия Ansible

[[00 Ansible]]

Ansible - инструмент управления конфигурацией, развертывания и оркестрации. Control node подключается к managed nodes преимущественно по SSH, передает модуль, получает результат и обычно не требует постоянно работающего агента.

# Преимущества

- читаемые YAML-playbooks;
- agentless-модель для большинства Linux-хостов;
- идемпотентные модули;
- единый inventory и переиспользуемые roles;
- режим проверки `--check` и отображение изменений через `--diff`.

Идемпотентность относится к конкретному модулю и его использованию. Команды `shell` и `command` сами по себе не гарантируют, что повторный запуск ничего не изменит.

# Основные примитивы

- `inventory` - хосты, группы и связанные переменные;
- `module` - единица действия, например `package`, `copy`, `template`, `service`;
- `task` - вызов модуля с параметрами;
- `play` - сопоставление группы хостов, переменных и списка задач;
- `playbook` - один или несколько plays;
- `role` - стандартная структура для переиспользования tasks, handlers, templates и defaults;
- `handler` - задача, запускаемая по уведомлению после фактического изменения;
- `facts` - сведения о целевом хосте;
- `template` - Jinja2-шаблон конфигурационного файла;
- `vault` - шифрование чувствительных переменных и файлов.

```yaml
# Устанавливает nginx и запускает handler только после изменения шаблона.
# Ожидаемо: первый запуск меняет пакет/конфиг, повторный сообщает changed=0.
- name: Настроить веб-сервер
  hosts: web
  become: true
  tasks:
    - name: Установить nginx
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Развернуть конфигурацию
      ansible.builtin.template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
        mode: "0644"
      notify: Перечитать nginx

  handlers:
    - name: Перечитать nginx
      ansible.builtin.service:
        name: nginx
        state: reloaded
```

```bash
# Проверяет playbook без применения изменений там, где модули поддерживают check mode.
# Ожидаемо: список предполагаемых changed-задач и итоговый PLAY RECAP.
ansible-playbook site.yml --check --diff
```

Короткий ответ: Ansible описывает желаемое состояние в playbooks и применяет его к inventory через модули. Его основные сильные стороны - agentless-доступ, читаемость, идемпотентность модулей и переиспользование ролей.
