# Pull и push модели

[[00 Ansible]]

В push-модели управляющий узел инициирует подключение к managed nodes и применяет конфигурацию. Обычный Ansible работает так через SSH.

В pull-модели агент или локальный процесс на каждом узле периодически забирает конфигурацию и применяет её. В Ansible для этого есть `ansible-pull`, обычно вместе с cron/systemd timer и Git repository.

Push проще контролировать централизованно и удобно запускать по событию. Pull лучше работает для автономных узлов и больших динамических парков, но требует расписания, защиты репозитория и контроля расхождений.

```bash
# Забирает playbook из Git и применяет его локально на узле.
# Ожидаемо: clone/update репозитория и обычный отчёт play recap.
ansible-pull -U https://example.org/infra.git site.yml
```
