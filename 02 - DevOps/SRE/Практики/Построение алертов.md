# Как строить алерты

[[00 SRE практики]]

Хороший алерт должен требовать действия.

Плохой алерт:
- шумит;
- не влияет на пользователей;
- не говорит, что делать;
- часто сам проходит;
- будит ночью без необходимости.

Лучше алертить по симптомам:
- вырос error rate;
- latency выше SLO;
- сервис недоступен;
- быстро горит error budget.

А не только по причинам:
- CPU 90%;
- диск 80%;
- под рестартнулся один раз.

Причинные метрики полезны для диагностики, но пользовательские симптомы лучше подходят для paging.

Короткий ответ:

Алерт должен быть actionable. Для paging лучше использовать симптомы пользовательской проблемы, а ресурсные метрики оставлять для диагностики или warning-уровня.
